## 电路接线

### 先通过网络收集各电路模块**使用方式**：

- #### TT马达（1：48）：

  > 作用：连接麦轮，控制麦轮转动方向和转速

  工作电压：3V\~6V；

  接线：两根引线；

  转动方向：根据两端输入电压大小决定；

  工作转速：由供电电压大小决定（3V 时约 90–125 RPM，6V 时可达约 200 RPM）；

  

- #### DC-DC降压模块（输出5V）：

  > 作用：降压（7.4V -> 5V）

  输入电压：4.5V ~ 40V（多数为 6~36V 或 8~28V）；
  
  输出电压：固定 5V，精度通常 ±3% ~ ±5%；
  
  转换效率：通常 85% ~ 94% ；
  
  | 引脚标识         | 功能     | 接线说明                     |
  | :--------------- | :------- | :--------------------------- |
  | **IN+ / VIN+**   | 输入正极 | 接电源正极（可接7.4V）       |
  | **IN- / VIN-**   | 输入负极 | 接电源负极（GND）            |
  | **OUT+ / VOUT+** | 输出正极 | 接负载正极（5V输出）         |
  | **OUT- / GND**   | 输出负极 | 接负载负极（与输入负极共地） |
  
  ###### 注意事项：
  
  - **禁止反接**：输入正负极反接可能瞬间烧毁模块。
  - **输入电压上限**：不要超过模块标称最高输入电压。例如某些模块输入超过25V可能烧坏芯片或降低寿命。
  - **散热**：输出功率超过10W时，务必加散热片。效率约90%意味着约10%的功率转化为热量。
  
  
  
- #### 两节18650电池：

  > 作用：给STM32系统板供电。

  作电源，输出7.4V直流电压。

  

- #### DRV8833电机驱动模块：

  |        参数         |            数值            |
  | :-----------------: | :------------------------: |
  | 电机电源电压（VM）  |        2.7 ~ 10.8 V        |
  | 逻辑电源电压（VCC） |        2.7 ~ 5.5 V         |
  | 单通道连续输出电流  | 1.5 A（RMS），峰值可达 2 A |

## 通电测试

- 测试**PS2通信**情况：通过接收器上的重锁定键重新锁定了PS2手柄。第一次通信测试**成功完成**。

- 测试4个**马达转动**情况：通入7.4V加上电驱后全部**正常运转**。

- PS2遥控**底盘运动**情况：

  **目标：推动遥感能够实现底盘的前进、后退、左右自转和斜对角底盘平移功能；**

  - **首次测试**：
    
    1. 现象：按下任意按键，马达无响应；**测试失败**；
    2. 调查：检差接线，无问题；检测源代码，发现代码出错；
    3. 原因：PS2在通讯时，STM32程序运行进入无出口循环中，从而导致无明显现象。首次测试失败。
    4. 改进：优化代码结构，加入行动保护模块代码。
    
  - **第二次测试**：
    1. 现象：推动摇杆能够完成全部目标功能，**测试通过**；
    2. 突发意外情况：断电后重新测试时，发现PS2无法正常配对；接着发现STM32系统板指示灯和接收器指示灯亮度偏暗；按下复位键时灯能够重新正常亮起，但松开时恢复微弱状态；
    3. 原因排查：
       - 硬件：（由于购买的万用表未到，只能通过快速触电法检测排除可能）
         1. 检测有无杜邦线脱落：检测重新接线后快速触电检测，未恢复正常；
         2. 检测是否是电池电量过低：更换电源重新测试。未恢复正常；
         3. 检测有无模块烧毁：依次断开各类模块触电检测，STM32系统板的指示灯仍然未恢复正常；
         4. 引脚检测：依次修改#define BRINGUP_HALT_LEVEL 的宏值，重新编译烧录，在全部模块断开时进行通电检测。结果：初步发现是PS2接收器出现问题。
         5. 检测PS2带载情况：无问题；同时发现STM32电源灯在空载时出现问题：亮度比连接STlink时暗；
         6. 检测STM32：最终发现STM32板LDO被击穿。
         7. 换了块新板后功能恢复。**问题解决**。
         8. 优化：电驱的供电线优化为独立的跳线（线更粗，加强导电负载能力）
       - 程序代码问题：虽然通过测试，但是遥控键位需要优化。
    
  - **第三次测试：**
  
    1. 改进说明：根据上一次的遥控情况，进行按键控制改进：
  
       | 输入               | 动作                                                         | 优先级    |
       | ------------------ | ------------------------------------------------------------ | --------- |
       | ✕                  | **真刹车**（DRV8833 双输入拉满 100%，绕组短路制动）          | 1（最高） |
       | △                  | 全速前进                                                     | 2         |
       | 方向键 上/下/左/右 | 按住 70% 平移；**同按两个 = 斜向**                           | 3         |
       | 左摇杆 Y           | 前后直行/后退，推杆距离 = 速度                               | 4         |
       | 左摇杆 X           | **原地自转**                                                 | 4         |
       | 右摇杆 Y           | 前后各绕一侧轮组：推前=左轮组动/右轮组 0（绕右），拉后反之   | 4         |
       | 右摇杆 X           | 绕**尾部中点**转（`vw = rx` + 横向补偿 `vy = vw·L/(lx+ly)`） | 4         |
  
    2. **测试现象**：底盘自转功能正常；上下左右平移较为正常（测试的地面是光滑瓷砖地面，存在轮胎打滑情况）；平移时轮胎转速不同导致阻力不能完全抵消。制动功能正常，全速前进功能正常；右摇杆的前后推拉功能累赘。在测试时，还发现有时在操作PS2时会突然出现mode转换，导致操作无反应。按下mode键后才可以重新操作。这种情况多发生在多键连续按下后。
    3. **需要改进地方**：
       
       - 用三角形和×键控制小车速度的挡位（档位可以分三档，慢速，中速，快速，外部表现为不同颜色的LED亮起），三角形把档位增加，X把档位减小。每个档位占据一个动力控制范围（慢速档：10%-40%；中速档：40%-70%；快速档：70%-100%。每档内又可以由左摇杆推动程度具体控制马达速度） 
       - 取消右遥杆的转弯累赘功能；改为左推动遥杆时，底盘绕左后轮水平旋转；向右推动时，底盘绕右后轮水平旋转。 
       - 想要实现两侧轮胎差速转弯功能；（可以先用右遥杆前后功能分别实现左快右慢，右快左慢，但马达动力不能超过当前档位的动力限制；如果实现不了就算了） 
       - 制动键改为SLECT键，全速前进键累赘删去。
       - 此外，L1/L2，R1/R2，用于控制两个舵机，方形键和圆形键可以用于控制机械爪上的舵机，实现爪的张合功能。
       - 优化心跳机制，定期（每10ms）调用一次PS2读取函数。
    4. **mode 突然掉线原因**：原因是**手柄自己掉出模拟模式**（`id` 变成 `0x41` 绿灯）。

    - 按键对应的运动已另存至  ***PS2按键分配.md  文件中***。

## 底盘运动

参考麦轮运动原理和解算原理，实现了最基本的运动功能：前后直行，向左、右自旋（绕底盘中心），绕左右后轮旋转，前后左右以及斜对角的平移，制动刹车，单侧轮同向运动功能。（有借助AI帮忙的成分，AI主要复责检查和修补代码和帮助我们找出问题的根源）

##### **设计中出现过的问题以及优化：**

- [x] **底盘平移之斜对角平移功能的分配：**
  - 问题起因：在原来的设计中，我们打算把平移功能设计为摇杆驱动（考虑到摇杆的全向控制）；但随后发现，平移功能的实际价值在我们此次的比赛中收益不大，不应该分配一个摇杆去控制平移。
  - 解决办法：我们把解决方向放在了十字键上面：发现十字键的上下左右可以通过复合信号实现控制底盘的斜向平移；同时按下两个十字键（相邻的），实现斜对角平移。（比如同时按下上和右，底盘向右上角平移）
  - 测试&实验：在测试中，通过PS2手柄上的十字键，我们成功控制小车的8向平移；功能测试通过。
- [x] **马达供电时电流超过导线承载能力：**
  - 问题起因：在设计档位控制时，实际操控发现在高速档（100%动力）时，STM32系统板会出现自动复位现象，产生一段时间的失联，影响操控流畅度。
  - 问题调查：上网查找资料、向AI提问后发现，是杜邦线的电流承载能力有限，无法承载马达全速运转时的电流大小，导致系统板自动复位保护电路。
  - 解决办法：由于来不及购买XT30/XT60总线替换杜邦线供电，我们考虑牺牲最大速度换取稳定的策略：将最大动力由原来的100%改为92%，降低最大动力上限控制电流大小，让电流在杜邦线的承载能力之内。
  - 实验检测：在实际测试过程中，自动复位现象发生的概率大大下降。同时，为追求流畅的操作手感，只能提高对操作手的要求：不要让底盘处于最大速度下长时间运动。

## 舵机运动

我们采用**3个舵机**（MG995，MG90S，SG90）来实现第一辆机器人的抓取方块的功能。

- **机械臂运动**

  使用MG995和SG90舵机控制机械臂2个自由度的运动。

  - 舵机分布：MG995位于机械臂的底部，连接底盘和机械臂；SG90位于两段臂的连接处，控制第二级机械臂的运动。
  - 控制模式：为了使机械臂的控制更加灵活，我们的两个舵机均采用了按键控制转动的方法：按下按键，舵机转动，松开按键，舵机停止转动；
  - 转动最大角度设计：暂定180°，充分发挥舵机的运动空间。（实际会根据机械臂之间的结构进行更加准确的运动角度限制）；

  

- **机械爪抓取**

  使用MG90S舵机控制机械爪的开合。

  - 舵机位置：位于机械爪的根部，通过齿轮联动实现爪的开合；

  - 控制模式：（待测试）采用右摇杆控制机械臂的开合控制方案，摇杆前推控制张开，后推控制闭合，开合的变化程度由时间和摇杆推动程度决定。（对比上一代方案来说，此方案让机械爪具有更多实用性，可控制的开合程度使得机械爪可以完成除抓取方块外的其他功能）

    - 关于控制模式的其他想法：打算让一个按键在不同情况下具有不同的控制功能。（设想为通过SELECT键切换按键的功能，使得一代控制模式和二代控制模式并存，以应对不时之需）

    > 一代方案为使用一键式的方式控制机械臂开合（已通过测试），即按下按键后机械爪合上，再按一次后机械爪张开；（在拿到具体的方块进行抓取测试后，发现一键式控制抓取无法精确控制抓取的力度，并不适合抓取给定大小的方块，同时也缺少灵活性，因此打算废弃，或者备用。）

  - 转动角度：结合具体的机械结构，根据测量，舵机可转动范围约为90°（在二代方案里面，需要重新限定转动角度）；

## 继电器控制

- [x] 最终测试通过 

采用常关模式和自锁模式进行控制供电。控制器可以一键控制整车的供电。

接线模式：

- 继电器供电：电源->继电器；
- 机器人各模块供电：继电器作为开关接入整车的供电总线，和电源进行串联。



**测试中发现的问题**：

- [x] 通电后无法正常控制底盘运动，猜测是继电器分压导致供电不足。

- **初步调查**：将电源越过继电器给机器人供电，发现操控恢复正常。

- **问题可能原因**：

  - **原因 A：继电器触点串在主回路里，压降太大 → MCU 欠压复位**

    4 个 TT 马达在 2S 下启动/堵转时峰值可到 **4~8A**，而普通继电器模块（如 SRD-05VDC）触点直流感性负载能力远低于标称的 10A，触点电阻随磨损会升到几十甚至上百毫欧 - > 电机一启动，电流一冲，**前级电压瞬间塌陷**，降压器输入掉到 5V 以下 - > MCU 复位。

  - **原因 B：继电器线圈供电不稳 → 触点"抖动/断开"**

    推摇杆 → 电机拉大电流 → 7.4V 轨被拉低 → 线圈吸力不足 → **触点弹开 → 全车断电（MCU 复位）** → 负载消失、电压回升 → 线圈重新吸合 → 又能动一下……

- 排差原因：借助AI分析，使用万用表排查。

  | 测量对象                   | 正常值       | 异常值                               | 测量结果 |
  | -------------------------- | ------------ | ------------------------------------ | -------- |
  | 继电器 **COM–NC 两端压降** | < 0.1V       | >0.3V → 原因 A（触点/端子电阻大）    | 差<0.10V |
  | 电池端电压 vs DRV8833 VM   | 差 < 0.2V    | 差很大 → 线径/接插件/继电器压降      |          |
  | 降压器**输入端**电压       | ≥ 6.5V       | 掉到 6V 以下 → 前级塌陷（A）         |          |
  | 板子 **5V / 3.3V 脚**      | 5.0V / 3.3V  | 掉到 4.6V / 3.1V 以下 → 就是它在复位 |          |
  | 继电器**线圈**两端电压     | ≥ 85% 额定值 | 掉到 70% 以下 → 原因 B               |          |

结合STM32的复位记录码，真正的问题是**断电式复位**；产生原因为：**继电器24V 线圈在 7.4V 下的"半吸合"造成的**。

- 解决方案：

  **方案（改动最小）：改变继电器接线方案，把 MCU 从继电器回路里摘出来**。

  ```
  电池 ─┬─► 继电器(COM/NO) ─► DRV8833 VM + 舵机电源
        └─► 降压器 5V ─► MCU（不经过继电器）
  ```

- 测试结果：测试顺利通过。继电器仅控制马达。



## 速度档位模块

- **原来需要解决的问题：**PS2手柄的摇杆控制速度的分辨度不够精确，难以满足微调底盘位置的要求。

- **想法来由：**想到汽车的分档位控制速度上限，由此联想到机器人的分档位控制。

- **初期想法：**

  - 设置3档模式：慢速档位（代码为0）：动力10%-40%；中速档位（代码为1）：动力40%-70%；快速档位（代码为2）：70%-100%；
  - 使用不同颜色LED指示当前所处的档位：黄灯：慢速；	绿灯：中速；	红灯：快速；
  - 默认启动时，处于档位1（中速档位），绿灯亮起；
  - 切换档位：占用PS2手柄上的三角形键（升档）和×形键（降档）；

- **实验验证：**测试通过，可以正常换档位，可以通过档位控制马达的最大速度上限。

- **发现问题：**

  - [x] 在最大档位时，易发生占空比过大，导致马达的供电线承载不住大电流；且发生时会出现自动复位现象；
  - [x] 低速档位不够“慢”；
  
  **解决办法：**
  
  对1：1. 用XT30/XT60总线替换杜邦线给马达供电；2. 降低快速档位的最大马力缓解杜邦线压力；
  
  对2：调节各档位马力范围；
  
  
  
-   **二次优化：**
  
    - 调节低速档为10%-30%；中速档为30%-60%；高速档为60%-92%；
    
    - 优化操控手感。具体为使底盘切换运动状态时更加流程。
